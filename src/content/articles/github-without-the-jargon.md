## First, find the front door

GitHub is a place where people host and collaborate on projects. A **repository** is a project's collection of files and history. Its **README** is usually the introduction: what the project does and where to start. You can read a public project without learning to program. See [GitHub's file guide](https://docs.github.com/en/repositories/working-with-files/using-files/viewing-and-understanding-files).

## A ZIP is not necessarily an app

**Code → Download ZIP** gives you source files: the ingredients, not necessarily a ready-to-run program. A **release** is a published project version and may include installers or other downloadable assets. Some projects offer only source code. Check the README's download links and [release notes](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases), and choose an asset for your OS and architecture. [GitHub explains source archives here](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives).

## Check where the link came from

Start from the creator's official website or a source-linked FRP article. Compare the repository owner and name, then follow the project's own download instructions. A similar name, popularity count or search advertisement does not prove a download is official or safe. If the destination is unexpected, stop and verify it. Do not disable security protections just to force an unfamiliar download to run.

## Make a home for your downloads

On **Windows**, open File Explorer with Windows + E. Open Downloads, press Ctrl + Shift + N, name the folder “FRP finds”, then press Enter. These shortcuts are documented by [Microsoft](https://support.microsoft.com/en-us/windows/keyboard-shortcuts-in-windows-dcc61a57-8ff0-cffe-9796-cb9706c75eec).

On **macOS**, open Finder, choose Downloads, then File → New Folder (Shift + Command + N). Name it “FRP finds” and press Return. See [Apple's folder guide](https://support.apple.com/en-gb/guide/mac-help/mh26885/mac).

Use a subfolder for each project and keep its source link in a note. Organizing a download does not install or verify it.

## Let the project teach its own installation

Follow the README's **Installation**, **Getting started**, or **Documentation** link for your chosen release. Read commands before running them. If it asks for unfamiliar developer tools, it may not offer a beginner installer; ask for help or choose something simpler. FRP explains the decision, while the project maintains its instructions.
